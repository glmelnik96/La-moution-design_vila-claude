# Рецепт адаптации серии

Используйте рецепт, когда новая серия, рубрика, выпуск или вариация сохраняет узнаваемую режиссуру, а текст, герой, значения или длительность меняются. Сначала откройте исходную композицию либо графический шаблон и соответствующий мастер. Если известно только имя архивной версии, укажите статус и источник. Привяжите рецепт к этой ревизии. Он одинаково применим к AE-композиции, редактируемой графике Premiere и HTML со шкалой кадров.

**Сохранить.** Зафиксируйте назначение каждого смыслового элемента, геометрию и начертание, соседство с лицом и субтитрами, характер входа и выхода, что зритель читает и что он видит сразу следом. Для тихого ролика источником события будет смена состояния или продукта. Для разговорного возьмите фрагмент реальной реплики и кадровый момент в новой версии. Укажите часы: кадры с нуля на таймлайне выходной секвенции, OUT исключён.

**Заменить.** Для нового выпуска запишите исходник, фактическую фразу, строки с переносами, имена или числа, нужные значения в редактируемом шаблоне и соответствующие опорные кадры. Время показа измеряйте между завершением появления и началом ухода. Допустимый темп чтения и число строк задавайте по брифу, кеглю и примерам серии. Проверяйте ширину по изображению. Изменение носителя или композиции может потребовать отдельного варианта рецепта.

**Рассчитать.** Из корня скилла запустите `node scripts/series-adapt.js recipe.json episode.json --out resolved.json`. Файл выхода должен быть новым. Без `--out` результат выводится в терминал. До рендера команда проверяет границы слотов, число строк, темп чтения по полностью видимому тексту и заданные привязки к речи. Она возвращает 0 при готовности к рендеру, 1 при редакторском замечании и 2 при неверных данных.

Один слот в рецепте может выглядеть так:

```json
{
  "series": "Вопрос перед ответом", "fps": "25/1",
  "template": "Шаблон карточки текущей утвержденной ревизии",
  "keep": ["Белый текст по центру на чёрном", "Перед ответом вернуть лицо"],
  "slots": [{
    "id": "question", "in": {"cue": "question"}, "out": {"cue": "speaker"},
    "enterFrames": 0, "exitFrames": 0, "maxLines": 4, "maxCharsPerSecond": 18,
    "checkCues": [{"cue": "word", "edge": "out", "window": [0,10]}]
  }]
}
```

Для нового выпуска подставьте его частоту, длину секвенции, слова и координаты. Допустимо использовать дробную частоту `30000/1001`. Для смещения относительно реплики добавьте `offset` в кадрах к `in` или `out`. В `checkCues` окно задаёт допустимое положение опоры относительно границы в кадрах, со знаком. Элемент необязателен. Если макет ограничивает ширину, укажите в слоте `maxWidthPx`, а в подстановке рядом с `lines` — массив `widthsPx` с измеренной шириной каждой строки в выходных пикселях. Измеряйте той же гарнитурой, размером и межбуквенным интервалом. Целая фамилия может выйти за край даже в одной короткой по числу символов строке.

```json
{
  "id": "Новый выпуск", "fps": 25, "frames": 300,
  "cues": {
    "question": {"frame": 100, "evidence": "монтажный стык"},
    "speaker": {"frame": 190, "evidence": "первый кадр героя"},
    "word": {"frame": 194, "evidence": "слово в исходном звуке"}
  },
  "values": {"question": {"lines": ["Как изменилась работа", "команды за год?"]}}
}
```

Для замены героя, состояния интерфейса, иллюстрации или фона задайте слоту `"kind": "visual"`, границы `in` / `out` и, если того требует бриф, `minHoldFrames`. В новом выпуске передайте `"values": {"hero": {"asset": "путь к новому источнику или слой композиции"}}`, где `hero` — ID слота. Параметры текста для визуального слота не нужны. Проверьте отведённую область, положение героя и состояние иллюстрации на кадрах из отчёта.

## Положение текста в карточке Premiere

Для Premiere-authored MOGRT со статическим текстовым слоем сравните два значения. Считайте исходный `Position` компонента `AE.ADBE Text` в шаблоне. Затем откройте экземпляр карточки в исходной монтажной секвенции и считайте тот же параметр на кадре удержания. Монтажёр мог сдвинуть текст после вставки. Зафиксируйте название и ревизию MOGRT в `recipe.template`, а проект, секвенцию, клип и кадр замера экземпляра — в `evidence`. Проверьте на мастер-кадре фактические переносы, гарнитуру и масштаб. `Motion`, `Vector Motion` и центр видимых пикселей относятся к другим координатам.

Добавьте к текстовому слоту `textLayout`. В этом условном примере позиция в шаблоне и позиция четырёх строк на таймлайне различаются. Оба значения — пары `[x,y]` в долях размера кадра с началом в верхнем левом углу. Сохраните точность исходного значения. Вариант хранит размер секвенции, где выполнен замер.

```json
{
  "textLayout": {
    "space": "normalized-sequence",
    "templatePosition": [0.5, 0.52],
    "variants": {
      "question-four-lines": {
        "lines": 4, "position": [0.5, 0.41], "frameSize": [3840, 2160],
        "evidence": "Секвенция-образец, V1, карточка вопроса с кадра 100, Text.Position"
      }
    }
  }
}
```

Укажите выходной размер в `episode.frameSize`, выбранный ключ в `episode.values.question.layout` и реальные строки в `lines`. Необязательное `episode.values.question.cardId` задаёт имя нового MOGRT, по умолчанию используется ID слота. Выбирайте вариант по утверждённому образцу с тем же оформлением и полями. Даже одинаковое число строк допускает несколько композиций. Для другой гарнитуры, ширины блока, пропорций кадра или иного размещения сохраните отдельный замер. Для анимированного Position, нескольких текстовых слоёв или мастера без исходного экземпляра оставьте вариант на проверку.

```sh
node scripts/series-adapt.js recipe.json episode.json --out resolved.json --cards-out cards.json
```

В `resolved.json` сохраняются источник, размеры обоих кадров, выбранный вариант и обе позиции. В готовом `cards.json` у каждой карточки с измеренной раскладкой будут `id`, текст с исходными переносами и `textPosition` экземпляра. При пропущенном замере, несовпадении количества строк, пропорций или другом замечании читайте `issues` в отчёте. Статус `review` оставляет сборку до разрешения замечаний. Существующие рецепты AE, HTML и визуальных слотов по-прежнему работают через `--out`.

Из корня скилла монтажа соберите карточку со стилем архивного MOGRT, указав пути к файлам выпуска.

```sh
python scripts/mogrtcard.py --template "donor.mogrt" --cards cards.json --out-dir cards --preserve-style
```

Вставьте новый MOGRT в чистую секвенцию в Premiere и экспортируйте кадр удержания до любых ручных перемещений. Приведите мастер к размеру экспортированного кадра и сопоставьте переносы, границы букв каждой строки по X и Y и наружные поля. Запишите расхождения и число ручных правок после импорта.

**Собрать и принять.** Заполните дубликат утверждённой композиции, HTML или MOGRT. Для простой карточки Premiere `premiere-autopilot/scripts/mogrtcard.py` принимает исходный шаблон и строки с переносами. Сохраните шрифт, размер, выравнивание и цвета исходной графики. Для графики над монтажом передайте вычисленный интервал и реплику через существующий `gfx-plan`. Сверьте кадры `checkFrames` на выходном видео при рабочем размере. Посмотрите переход с предшествующей сцены, первую полностью читаемую строку, последний кадр удержания и следующее действие. Проверьте изменённый текст в изображении, поля, переносы, перекрытия, время чтения и совпадение акцента со звуком. Для предельного имени или числа проверьте отдельную подстановку. Когда тайминг не проходит, сначала пересмотрите переносы, формулировку или длительность карты. Сохраните мастер-образец, заполненный рецепт, редактируемый вариант и проверенный фрагмент.
